测试素材通过仅监听主机回环地址的临时 HTTP 服务，经 hdc 反向端口映射下载到系统文件库。应用本身的两端同步使用 Engine P2P；临时 HTTP 服务只提供测试输入和本地校验页。接收端从历史导出，经系统选择器选择文件，在浏览器本地 Web Crypto 计算 SHA-256；校验页不上传文件。成功以接收历史、发送回执、导出完成提示与字节哈希共同判定。

反向导出第一次在保存后立即切换浏览器，应用报告导出未完成，留下 0 字节输出；重新导出并等待“已导出文件”后得到正确 36 字节。未把失败尝试计为成功，也未删除用户选择的输出。历史现象仍需在当前包中复验；不能仅凭代码推断归因。后续统一操作反馈已清理旧提示，但后台中断和提供方差异仍待验收。

零字节 empty.txt 能由系统选取，但发送失败。源码确认 Engine 的 import_host_files 明确拒绝 size_bytes == 0；当前不能宣称支持空文件，不能以 Host 空文件写入测试代替发送验收。多文件一次选择、大文件、取消、磁盘不足和真机 URI 授权仍未验收。

剪贴板文件读取发现局部缺陷：getPrimaryUri 只取一项，而写入能产生多条记录，导致再次读取时丢失后续文件。现替换为遍历 PasteData.getRecord，保留全部 URI 的顺序与编码，拒绝缺失 URI 的文件记录，忽略非 URI 描述记录；没有保留旧的单项读取路径。4 项新增测试修复前均失败、修复后通过。当前客户端 Node 72/72 通过，Host 子集 54/54 通过，API 26 Release 编译通过。系统多 URI 剪贴板实测仍待执行。

图片测试确认浏览器“复制图片”得到 pixelMap 记录，ImageKit 能编码为 138 字节 PNG，但旧 Engine sendImage 参数使用 Node Buffer，鸿蒙传入 Uint8Array 时在绑定转换失败。修复已完成并重新生成 HAR/HAP，设备结果见下一节。
