# 产品范围与交付计划

## 产品边界

用户拥有的鸿蒙设备作为完整 P2P 对等成员，与桌面及其他支持端共享空间。所有加密、配对、成员管理、历史、搜索和传输规则归 Engine；鸿蒙 Host 只适配系统能力。第一阶段以文本验证全链路，最终交付仍包括完整计划。

| 阶段 | 交付 | 通过依据 |
| --- | --- | --- |
| M0 | 规格、版本、权限和签名方案 | 本目录文档、engine-lock.json、实际系统确认 |
| M1 | HAR 加载、启动、关闭、错误映射 | API 24 或更新版本编译结果和设备日志；当前验证 API 26 |
| M2 | 安全存储、剪贴板、文件句柄 | 真机读写、权限拒绝、重启、URI 释放 |
| M3 | 创建/加入/取消、邀请、成员列表/移除 | 两设备配对及重启身份保持 |
| M4 | 双向文字、加密历史、搜索、去重 | 两设备内容比对、回环测试和存储扫描 |
| M5 | 图片同步与预览 | 多格式、内存、大图、中断恢复 |
| M6 | 文件同步、进度、取消和恢复 | 多文件、中文、空格、大文件、磁盘不足 |
| M7 | 系统限制及恢复 | 前后台、锁屏、回收、Wi-Fi/蜂窝切换 |
| M8 | Beta 交付 | 全矩阵、安全检查、签名 HAP、校验和及说明 |

## 基线与约束

- 当前包名 `app.uniclipboard.harmony` 是开发包名，发行前确认最终标识和签名身份。
- 官方 Engine v1.1.0-rc.22 要求 API 24，仅提供 arm64-v8a 鸿蒙产物。
- 默认只在前台处理剪贴板与连接。是否支持额外后台能力必须根据实际 SDK 和真机结果决定；不能声称无限常驻。
- 不保存明文历史、邀请码、口令、设备名和文件路径；UI 中的临时数据仅驻留内存。
- 文件本体及受管缓存 basename 依 Engine 文档允许例外，不宣传所有缓存均加密。
- 重试和传输恢复以 Engine 为准，宿主不另建离线历史发送队列。
- 配对 pending/processing 不是成功；发送 accepted、duplicate、offline、pending 和 error 分开呈现。

## 接口与验收状态

官方锁定版本仍为 v1.1.0-rc.22。发现的 N-API 声明漂移及产品所需接口已在 Engine 开发源码中统一，产品当前使用经过开发清单校验的本地 API 26 HAR；声明从同一 HAR 提取，不在产品侧补写不存在的方法。本地包不等同于官方发布版本。

两个 API 26 模拟器已验证配对、双向文字、双向文件导出哈希、图片接收与预览，以及部分重启恢复。受限诊断导出已通过两端系统保存测试。完整设备、网络、安全和发布矩阵仍未通过，各阶段是否完成以 [验收记录](verification.md) 的证据为准，不能仅按页面或接口是否存在判定。
